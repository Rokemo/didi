# 跟单进度跟踪 · 本地网页原型 v0.2

本原型把 `倍优跟单进度表（模板）_v10.xlsx` 的核心能力搬到一个**本机可跑的网页**：
数据存进本地 SQLite 文件，支持多人协同录入 + 驾驶舱看板 + 逾期呆滞 / 合同冗余判定。

## 启动（本地）
双击 `run.bat`（首次会自动从 v10 导入数据并启动服务），浏览器打开：
```
http://127.0.0.1:8731
```
若 WPS 不可用导致导入失败，会自动生成结构化**种子数据**用于演示。

**默认账号**（首次启动自动创建，请尽快改密码）：
| 用户名 | 密码 | 角色 | 权限 |
|--------|------|------|------|
| admin | admin123 | 管理员 | 全部读写 + 删除 + 备份 |
| zhang | zhang123 | 跟单员 | 可录入/编辑 原始数据、发货需求；不可删除、不可改产品/预测 |
| view | view123 | 只读 | 仅查看 |

> 改密码：用 `sqlite3 tracker.db` 执行
> `UPDATE users SET password_hash='盐:哈希' WHERE username='admin';`
> 或用代码 `hash_pw('新密码')` 生成（见 server.py）。

## 功能（v0.2 新增）
- **登录 + 权限**：未登录一律 401；按角色显隐按钮（删除仅管理员，录入限跟单员/管理员）。
- **录入体验打磨**：
  - 批量粘贴导入：在「原始数据」页点「批量粘贴导入」，从 Excel 复制含表头的多行直接粘贴，
    按中文表头自动匹配列，后端**逐行校验**后写入（错误行单独列出，不阻断其他行）。
  - 字段校验：合同号/产品编号必填；数量/单价必须为非负数值；日期格式 `YYYY-MM-DD`。
  - 跟单员维度筛选：原始数据页可按 **运营专员 / 运营组别 / 厂商** 下拉过滤。
- **核心逻辑做真**：
  - 逾期呆滞：以「交货日期 < 基准日 且 未到货>0」判定逾期，分 5 档（0-30/31-90/91-180/181-365/365+）；
    呆滞 = 超 90 天无跟进。汇总逾期行数/金额/呆滞行数，可按维度过滤。
  - 合同冗余判定：按 **运营组别 / 厂商 / 产品编号(公司级) / SKU×运营专员** 聚合未到货金额；
    交付周期 6 档；接单判断 = 按销售预测未来3月量分 S/A/B/C 级 → 安全库存(月均×系数) →
    公司级冗余 > 安全库存 则「不可接单」（预测为空显示「待填预测」，放行不报错）。
- **驾驶舱 / 三张源表 / 备份**：保留并增强。

## 数据在哪里
- 主数据库：`tracker.db`（单文件，落盘持久化，关机/断电不丢）。
- 备份目录：`backups/`（启动时自动备份一份）。
- 重新导入：`python import_data.py`。

## 防丢建议（重要）
1. 每次重要操作后点「备份」；或配置 Windows 计划任务每日跑一次 `backup.py`。
2. 把 `backups/` 同步到网盘（OneDrive / 百度网盘 / 腾讯微云），实现异地冗余。
3. 备份文件建议加密（跟单数据含工厂/客户信息，属商业敏感）。

## 部署到「常开机器 / 云」指引（多人协同）

原型默认只绑 `127.0.0.1`（仅本机）。要让团队/工厂从任何地方访问，按下面任一步走。

### 方案 A：办公室一台常开机器（零月费）
1. 选一台不关机的电脑（Win/Linux 均可），装好 Python 3.10+。
2. 把整个 `tracker_web/` 目录拷过去。
3. 让服务监听局域网：`set HOST=0.0.0.0 && python server.py`（或 `run.bat` 里加这行）。
4. 防火墙放行端口 8731（入站规则）。
5. 同事用 `http://这台机器的内网IP:8731` 访问。
   - Windows 设为开机自启：把 `run.bat` 丢进「启动」文件夹，或用 `nssm`/`sc` 注册成服务。
6. 备份：仍按上面「防丢建议」配计划任务 + 同步网盘。

### 方案 B：云服务器（异地/外地访问）
1. 租一台**轻量应用服务器**（腾讯云/阿里云，约 50–100 元/月，1 核 2G 足够撑几万行）。
2. 装 Python，scp 上传 `tracker_web/`。
3. 后台常驻：`HOST=0.0.0.0 PORT=8731 nohup python server.py &`（或 systemd / supervisor 托管）。
4. **反向代理 + HTTPS（强烈建议）**：
   - 装 Nginx，把 80/443 反代到 `127.0.0.1:8731`；用 Let's Encrypt 免费证书启用 HTTPS。
   - 不要直接把 8731 暴露公网裸端口。
5. 数据库仍是单文件 `tracker.db`，**整个目录打包即迁移**，无需导出。
6. 备份：定时 `backup.py` 并把 `backups/` 传到对象存储 / 云盘。

### 安全必做
- ⚠️ **第一件事改掉三个默认密码**（尤其 admin）。
- 公网务必走 HTTPS + 反向代理；`HOST=0.0.0.0` 仅限可信内网/反代后。
- 如需更细权限（按跟单员只能看自己数据），在 `can_write` / `do_GET` 里加 `username` 过滤即可（代码已留角色钩子）。
- 数据量更大时，可把 SQLite 换成 PostgreSQL（仅需改 `conn_db()` 的连接串 + 少量 SQL 方言）。

## 技术栈
- 后端：Python 标准库 `http.server` + `sqlite3`（**零外部依赖**）。
- 前端：原生 HTML/JS + Chart.js（CDN）。
- 端口：8731（可用环境变量 `PORT` 改；`HOST` 改绑定地址）。

## 说明
- 这是**原型**：录入 + 看板 + 逾期/冗余判定已可用。原 Excel 中约 160 万公式格的逻辑
  （甘特图、9 道工序状态机、整列 SUMIFS 聚合）尚未 1:1 移植，后续按需逐步迁移。
- 接单判断的「安全库存系数」「交付周期分档阈值」为可配置常量（见 server.py `GRADE_FACTOR` / `OVERDUE_BUCKETS`），
  如与你们内部口径不同，改这两处即可。
