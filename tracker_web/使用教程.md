# 跟单进度跟踪 · 网页版使用教程

> 适用对象：采购跟单、工厂对接、运营、以及需要查看进度的管理人员。
> 这是一份面向**最终使用者**的操作手册，按左侧导航的模块逐个讲清楚「是什么 / 怎么用 / 注意什么」。
> 系统版本口径：清爽浅色版（前端 r5）。所有数据存在本地 `tracker.db` 单文件里。

---

## 一、三分钟上手

### 1. 打开网站
- 本机使用：双击 `启动.bat`，会自动开浏览器并访问 `http://127.0.0.1:8731`。
- 如果没自动弹出，手动在浏览器地址栏输入上面的地址。
- 左侧是**分组导航**，右侧是内容区。点左侧任意一项切换模块。

### 2. 登录说明（重要）
- **当前默认是「免登录」模式**：任何人打开网址就是「管理员」，可以直接增删改全部数据。
- 正因为免登录，把网址发给别人前请确认环境可信（见末尾「给团队用」一节）。
- 若你希望**分账号、分权限**使用（管理员 / 跟单员 / 只读），让部署者在启动前设置 `AUTH_ENABLED=1` 并创建账号即可，页面会自动出现登录框与角色徽章。账号角色说明见第五节。

### 3. 通用操作（每个表格页都一样）
- **搜索框**：输入合同号、产品、团队、运营、厂商等关键字，点「搜索」。
- **下拉筛选**：按「跟单员 / 运营组别 / 厂商」等维度快速过滤。
- **分页**：表格底部有翻页，可跳页。
- **行内编辑**：大多数表格点行尾「编辑」按钮，在弹窗里改完点「保存」。
- **导入 Excel**：资料类模块有「下载模板 → 从 Excel 导入」，按模板列填好直接上传。
- **新增 / 删除**：带 `+ 新增` 的按钮可加一行；带「删」的按钮（仅管理员可见）可删整行。

## 二、各模块详解

左侧导航分为 6 组。下面按组逐个说明。

---

### 组 1 · 概览

#### ① 驾驶舱（首页）
**用途**：一眼看全局健康度，不适合逐行操作，适合每天开工先扫一眼。

你会看到：
- **6 张 KPI 卡**：在手订单量、在手金额、逾期行数、逾期金额、呆滞行数、整体完成率等关键数字。
- **完成率环形图**：所有订单已完工工序占比。
- **各厂商在手金额 Top10**：哪个工厂占压资金最多，条形越长越多。
- **各运营组别逾期分布**：哪个运营组逾期最严重。

**操作**：无需操作，纯看板。基准数字来自「原始数据」与「工序进度」两个数据源，数据更新后刷新页面即变。

---

### 组 2 · 生产进度

#### ② 工序进度（核心模块）
**用途**：跟踪每个合同 / 每个 SKU 的 **9 大生产工序**走到哪一步了——这是跟单日常最常用的一页。

9 大统一工序（状态色块从左到右）：
`下料 → 焊接-大件 → 焊接-小件 → 喷涂·底漆 → 表面处理-大件 → 表面处理-小件 → 坐垫·软装 → 装配 → 包装`

> 注：不同工艺类目（特斯林 / 编藤 / 铁艺铝艺 / 树脂等）在「产品资料」里登记后，页面会把统一工序名映射成该类目的本地名（例如铁艺的「焊接-大件」），但进度逻辑一致。

**数据来源（关键区别）**：本模块是**独立数据源**，不依赖「原始数据」表。你必须单独把工序明细从 Excel 导入进来（见下），之后页面按「产品编号 + 合同号」自动汇总成进度矩阵。改原始数据表**不会**影响这里的进度。

**怎么用**：
1. **首次导入**：点「下载模板」拿到 Excel，按模板填好每一条「工序明细」（哪张合同、哪个产品、哪道工序、实际完成日期），点「从 Excel 导入」。
2. **查看进度矩阵**：每一行是一个「合同×产品」，9 个色块表示 9 道工序状态：
   - 灰 = 未开始；蓝 = 进行中（已填部分工序）；绿 = 已完成；琥珀 = 预警；红 = 逾期。
3. **Excel 式列筛选（推荐）**：点任意**列表头的 ▼**，可对该列：
   - 排序（升 / 降 / 无）；
   - 按值筛选（文本包含，或勾选多个具体值）；
   - 隐藏此列。
   点弹层外部自动关闭。
4. **列名编辑**：点工具栏「列名编辑」，可显示 / 隐藏某些列、调整列顺序、重置默认。设置存在浏览器本地（换电脑不共享）。
5. **批量更新工序进度**：勾选多行（或勾表头全选当前页）→ 点「批量更新工序进度」→ 选要更新的**工序**（9 大工序之一）+ 填实际完成日期（留空 = 清除该工序进度）→ 确认。支持「应用到当前搜索 / 筛选下的全部行」。
6. **看明细**：每行末「明细」按钮，查看这一行导入的原始工序明细。

**注意**：
- 工序进度与原始数据是两个库，务必各导各的，别指望改一处另一处跟着变。
- 批量更新需要写权限（免登录模式下所有人可操作）。

#### ③ 甘特图（22 周滚动）
**用途**：看每张合同在未来约 22 周内的计划排产条，识别哪些合同挤在同一周、哪些可能撞期。

**怎么用**：
- 顶部可按「跟单员 / 运营组别 / 厂商」筛选，可改「基准日」。
- 表格以周为列，每个合同一行，色条长度 = 计划生产跨度（由工序节拍参数推算）。
- 用于排产协调，不在此录入数据。

**注意**：计划日期由「参数·字典」里的工序节拍推算，节拍没填对则甘特不准（见模块 ⑬）。

#### ④ 逾期呆滞
**用途**：揪出已经过了交货日却还没到货的合同，以及长期没动静的呆滞单。

**判定口径**：
- **逾期** = 交货日期 < 基准日 且 未到货数量 > 0。
- 逾期分 5 档：`0-30 天 / 31-90 天 / 91-180 天 / 181-365 天 / 365 天以上`。
- **呆滞** = 超 90 天仍无到货跟进（会单独统计）。

**怎么用**：
- 顶部设「基准日」（默认今天），可按运营组 / 跟单员 / 厂商 / 逾期档筛选。
- 上方两张图：按分档的行数、按分档的金额。
- 下方表格列出每条逾期记录，方便逐单催工厂。

### 组 3 · 订单与合同

#### ⑤ 原始数据（主数据源）
**用途**：这是整个系统**最基础的一张表**——所有订单的合同号、产品、数量、单价、交货日期、厂商、跟单员等都录在这里。绝大多数汇总（驾驶舱、订单明细、合同汇总、逾期、甘特）都从它算出来。

**怎么用**：
- **录入方式三选一**：
  1. 点「+ 新增一行」手工填；
  2. 点「从 Excel 导入」上传整张表；
  3. 点「批量粘贴导入」——**最省事**：从你的 Excel 选中多行（含表头）复制，粘贴到弹窗文本框，系统按中文表头自动匹配列，逐行校验后写入（错误行单独列出，不阻断其他行）。
- **筛选 / 搜索**：按跟单员、运营组别、厂商下拉过滤，或输关键字搜。
- **删除**：管理员可勾选匹配项（含「全选所有匹配项」跨页整批删）后「批量删除」。**删除不可逆，谨慎操作。**

**字段校验**：合同号 / 产品编号必填；数量 / 单价须为非负数；日期格式 `YYYY-MM-DD`。

#### ⑥ 订单明细（02）
**用途**：在原始数据基础上，按「合同号 + SKU」双键展开的明细视图，并补充「待交付数量、合同总数、数量档位」等派生列，方便逐合同逐 SKU 盯交期。

**怎么用**：纯查看 + 筛选（跟单员 / 运营组 / 厂商 / 搜索）。数据来自原始数据，无需单独录入。

#### ⑦ 合同汇总（06）
**用途**：按「合同号」归集每张合同的总量、总金额、已到货 / 未到货等，一张表看清每个合同全貌。

**怎么用**：顶部设「基准日」，下方表格自动汇总。适合跟客户 / 工厂对账前先自查。

#### ⑧ 合同冗余（11）
**用途**：判断哪些产品「备货太多、可能接不动单」——即公司级库存 + 在制约 > 安全库存时，提示「不可接单」。

**判定口径**：
- 按 4 个维度聚合未到货金额：**运营组别 / 厂商 / 产品编号（公司级）/ SKU×运营专员**（顶部子标签切换）。
- 交付周期分 6 档；接单判断 = 按销售预测未来 3 月量分 **S / A / B / C** 级 → 安全库存（月均 × 系数）→ 公司级冗余 > 安全库存 则「不可接单」。
- 预测为空时显示「待填预测」，放行不报错（所以**销售预测要先填**，这一页才准）。

**怎么用**：顶部设「基准日」，切子标签看不同视角，下方表格给出冗余金额与接单结论。

---

### 组 4 · 资料库

这三个模块是「基础档案」，被其它模块引用，建议**最先维护**。

#### ⑨ 产品资料
**用途**：登记每个产品的档案（产品编号、中文品名、工艺品类、SPU 等）。「工艺品类」决定工序进度的本地工序名；「SPU」用于工序进度按产品匹配。

**模板列**：产品编号*、中文品名、工艺品类、SPU（* 必填；表头中文自动识别）。
**怎么用**：「下载模板 → 从 Excel 导入」或「+ 新增」。

#### ⑩ 发货需求
**用途**：记录每个 SKU 计划什么时候发、发多少，是「发货需求判断」模块的输入。

**模板列**：产品编号(SKU)*、团队*、运营专员、厂商、跟单员、发货数量*、发货时间(YYYY-MM-DD)*。
**怎么用**：同上，导入或新增。

#### ⑪ 销售预测
**用途**：登记每个产品未来 3 个月预计出货量，分 S/A/B/C 级，是「合同冗余」「接单判断」的依据。

**模板列**：产品编号*、运营专员*、未来3月预计出货数量*。
**怎么用**：同上。

---

### 组 5 · 分析

#### ⑫ 发货需求判断（10）
**用途**：在指定时间窗口内，比较「需求 vs 供应」，判断是否能按时发货。

**怎么用**：
- 顶部设「开始日 / 结束日」，点「计算」。
- 逻辑：需求 = 发货需求表里该窗口内的发货量；供应 = 原始数据表里未入库数量；差额 = 供应 − 需求（≥0 即满足）。
- 结果表逐 SKU 给出「满足 / 缺口」，方便提前调货。

---

### 组 6 · 系统

#### ⑬ 参数 · 字典 · 标准（07 / 08 / 09）
**用途**：这是整套算法的「单一真相源」，普通使用者一般**只看不改**，由管理员维护。

包含三块：
1. **工序节拍（07）**：计划开工 = 合同日 + a，计划完工 = 出货日 + b。决定甘特图与计划日期是否准。
2. **阈值与字典（08）**：逾期预警阈值、类目映射等（页面以卡片展示）。
3. **检验标准（09）**：产中检验的参考重点，跟单巡厂时对照用。

**注意**：节拍 / 阈值改错会连带影响甘特、逾期等所有依赖项，非管理员不要动。

#### ⑭ 数据备份
**用途**：一键把 `tracker.db` 复制一份带时间戳的副本到 `backups/`（自动保留最近 30 份）。

**怎么用**：点「立即备份」，看到成功提示即可。
**强烈建议**：重要操作后随手备一份；再配 Windows 计划任务每天自动备，并把 `backups/` 同步到网盘（OneDrive / 百度网盘等）做异地冗余。跟单数据含工厂 / 客户信息，属商业敏感，备份建议加密。

## 三、推荐的数据录入顺序

1. **先建档案**：产品资料（⑨）→ 发货需求（⑩）→ 销售预测（⑪）。
2. **再录订单**：原始数据（⑤）——这是主数据源，务必先有它，订单明细 / 合同汇总 / 逾期 / 甘特才有数。
3. **独立录工序**：工序进度（②）单独从 Excel 导入明细（它不依赖原始数据）。
4. **最后看分析**：驾驶舱、逾期呆滞、合同冗余、发货需求判断都基于上面四步，数据齐了才准。

## 五、账号与角色（启用密码登录后）

默认免登录 = 全员管理员。若部署者开启了账号体系，角色如下：

| 角色 | 能做什么 | 不能做什么 |
|------|----------|------------|
| 管理员 | 全部读写 + 删除 + 备份 + 改参数 | — |
| 跟单员 | 录入 / 编辑 原始数据、发货需求、工序进度 | 不能删整行、不能改产品资料 / 预测 / 参数 |
| 只读   | 仅查看所有页面 | 任何编辑 / 删除 / 导入 |

按钮会按角色自动显隐（例如「删除」仅管理员可见，「批量更新工序进度」需写权限）。

## 六、给团队 / 外部使用（部署与分享）

> 把网址发给别人前，先想清楚「谁能用、安不安全」。

### 方案 A：同一办公室（零月费）
1. 选一台不关机的电脑，装好 Python 3.10+，把 `tracker_web/` 整个目录拷过去。
2. 让服务监听局域网：启动前设 `HOST=0.0.0.0`（或改 `启动.bat`），再运行。
3. 防火墙放行 **8731 端口（入站）**。
4. 同事用 `http://那台机器的内网IP:8731` 访问。
5. 设为开机自启：把 `启动.bat` 放进「启动」文件夹，或用 `nssm` / `sc` 注册成服务。

### 方案 B：云服务器（异地 / 外地工厂访问）
1. 租一台轻量云服务器（约 50–100 元/月，1 核 2G 足够几万行）。
2. 装 Python，上传 `tracker_web/`，后台常驻 `HOST=0.0.0.0 PORT=8731 python server.py &`。
3. **务必加 Nginx 反代 + HTTPS**（Let's Encrypt 免费证书），不要让 8731 裸端口直接暴露公网。
4. 数据库是单文件 `tracker.db`，**整个目录打包即迁移**，无需导出。

### 方案 C：临时外网（快速演示）
- 在本机跑 `cloudflared tunnel --url http://localhost:8731` 会得到一个 `*.trycloudflare.com` 临时网址，立即可用、无需域名，但**每次重启地址会变、关掉即失效**，仅适合临时演示。
- 命名隧道（固定地址）在国内网络不稳定，长期稳定外网建议走方案 B 或国内内网穿透（花生壳 / cpolar / frp + 轻量 VPS）。

### 安全必做
- ⚠️ **第一件事：如果开了账号，立刻改掉默认密码**（尤其 admin）。
- 公网务必 HTTPS + 反代；`HOST=0.0.0.0` 仅限可信内网或反代之后。
- 跟单数据含工厂 / 客户商业信息，备份加密 + 异地冗余。
- 多人写同一库时，SQLite 适合轻量并发；人多用 PostgreSQL 更简单（改连接串即可）。

## 七、常见问题

**Q：页面打开是旧版 / 按钮点不动？**
A：浏览器可能缓存了旧 JS。强制刷新（Ctrl+F5）一次即可。

**Q：工序进度表是空的？**
A：它是独立数据源，需要单独「从 Excel 导入」明细，不会从原始数据自动来。

**Q：逾期 / 甘特数字不对？**
A：先确认「原始数据」里交货日期、未到货数量已填；甘特还要看「参数·字典」的工序节拍是否准确。

**Q：导入 Excel 报列匹配不上？**
A：用页面「下载模板」拿标准表头，表头用中文关键字（如「合同号」「产品编号」「交货日期」）即可自动识别，不必完全一致。

**Q：误删了数据？**
A：去「数据备份」恢复最近的 `backups/` 副本，或联系管理员从备份还原 `tracker.db`。删除操作本身不可逆。

**Q：换电脑后列名编辑 / 筛选设置没了？**
A：这些个性化设置存在浏览器本地，不跨设备共享，属于正常现象。
